# 条件性队列模拟 v1

目的：在预先明确的关联、工作容量和信息成本假设下，检验现有复核规则改变处理顺序的收益及失败条件。此模拟不验证假设在现实中成立，不估计真实解决率。

输入固定为已有20条竞赛合成样例，10条规则命中、10条匹配未命中。由当前 model.py 重新计算规则标记。样例人为富集了命中者，不能代表完整客服队列。优先级构成需报告。

两策略：A先Critical再High，同级随机顺序（没有可信到达时间，不能称为FIFO）；B保持相同优先级，仅在同级内把规则命中者提前。两组共享每次运行的随机打破并列次序和逐案例潜在结果，不给B额外修复能力。

预算20个抽象时间单位，每处理一个案例消耗2单位、最多尝试一次。A无额外信息开销；B全队列的信息处理开销预设为0、2、4、6、8单位，容量为floor((20-开销)/2)。这些单位及开销是假设，不是测得的分钟数。未选中的案例不能通过本次模拟额外处理解决；这不描述其正常支持结果。

模拟器为每例产生“本次处理可解决”的隐藏二元结果，排序策略不可读取。三个世界的命中/未命中可解决概率预设如下：

- 正向关联：0.8 / 0.2；
- 无关联：0.5 / 0.5；
- 反向关联（命中者更难解决）：0.2 / 0.8。

这些概率完全是未校准的情景参数，不来自比赛观测。正向情景把有利关联作为前提，其结果不能反过来证明规则有效。潜在结果在同一次运行内对两策略相同，策略只改变选中集合。

每个情景运行10000次，每次仍是固定20案例，种子20260918。重复减少蒙特卡洛计算误差，不增加真实独立样本。只执行冻结的情景矩阵，不挑最好结果、不调整阈值救结果。

主要量：预算内模拟解决数/全部20案例，以及B-A配对差。另报处理构成、解析条件期望、蒙特卡洛标准误和单次运行差的5%—95%范围。不能称这些为真实业务置信区间。

核对：按每个优先级的命中/未命中构成独立计算期望并与模拟核对；在容量足以处理全部20例且无开销时，两策略应逐次得到相同结果。无关联情景的零开销解析增益应为零。

最终只判断：给定哪些假设，排序可带来多大模拟收益；何种条件使收益消失或反转。真实业务效果、需求和问题诊断能力不在本实验已验证范围。
