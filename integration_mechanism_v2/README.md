# 套餐与集成：已记录背景能解释这种关联吗？

**可以继续研究，本轮补做了一个此前未检验的问题：公司规模、行业、地区、产品构成及使用量，能否替代套餐对集成数量的解释？结果是，在固定的加性线性模型中不能。套餐与集成的条件关联仍然很强，但没有识别套餐权限、需求自选、数据生成规则或配置协助中的哪条机制成立。**

本轮只用比赛原始合成数据，没有新造客户或升级结果，没有执行真实配置帮助；此前模拟和真实试点的状态保持不变。

## 方法和范围

8,320名客户各占一行。结果变量为每客户2023年1至5月、全部产品月记录的平均集成数量，不是去重集成总数。42,210条使用记录构成8,442个完整五个月客户产品组合，没有将产品月行当成独立客户。

在看本轮结果前记录[固定方案](protocol.md)，比较五个含截距OLS模型：

- P：套餐类别。
- B：公司规模、行业、地区类别，以及各产品在该客户记录中所占比例。
- U：客户平均会话数、操作量、协作人数分别取log1p。

Active Days不进入模型，不因该字段此前发现的日历越界删掉客户。所有模型使用相同8,320人。公司规模类别较粗，使用量不等于真实业务需求，产品选择和使用量可能受套餐影响，因此这些变量不能自动视为有效的因果调整集。

复用原integration_plan_v1按套餐、客户哈希划分的6,654人训练与1,666人测试名单。类别水平和测试预测参数只从训练客户拟合；没有未知测试类别，各设计矩阵满秩。这个测试集此前已使用，本轮是重复使用的内部泛化复核，不是新确认集、未来升级预测或外部验证。

## 完整结果

R²衡量对应模型解释集成数量差异的比例；各行的预测目标与客户分母相同。

| 模型 | 全部8,320人拟合R² | 原1,666人测试集R² | 测试MSE |
|---|---:|---:|---:|
| 仅套餐 P | 87.9344% | 87.2648% | 0.349669 |
| 仅背景 B | 0.3965% | −0.8075% | 2.767853 |
| 背景＋套餐 B+P | 87.9946% | 87.2652% | 0.349657 |
| 背景＋使用量 B+U | 18.4134% | 17.6981% | 2.259749 |
| 背景＋使用量＋套餐 B+U+P | 87.9968% | 87.2566% | 0.349893 |

只用背景的测试R²为负，表示其预测误差高于以测试集均值作参照的误差，并非负的因果效应。

加入套餐后，背景模型全队列R²增加87.60个百分点；背景和使用量模型增加69.58个百分点。在重复使用的测试集上，后一增加为69.56个百分点，MSE减少84.52%。这不是套餐造成的升级或利润增量，也不是因果独立贡献。

反过来，在仅套餐模型上增加背景及使用量，测试R²从87.2648%变为87.2566%，没有显示实质预测改善。不能因此证明这些字段在其他任务、非线性模型或真实客户中没有价值。

## 同公司规模内仍有套餐差异

六个公司规模层都覆盖四种套餐；24个单元最少131人、最多913人，没有空单元。每个规模层中，客户平均集成数都依次为Free < Standard < Premium < Enterprise。

| 公司规模 | Free | Standard | Premium | Enterprise |
|---|---:|---:|---:|---:|
| 1–10 | 1.06 | 2.36 | 4.14 | 5.79 |
| 11–50 | 1.21 | 2.42 | 4.13 | 6.02 |
| 51–200 | 1.13 | 2.39 | 4.06 | 6.04 |
| 201–500 | 1.07 | 2.42 | 4.08 | 6.04 |
| 501–1000 | 1.21 | 2.42 | 4.14 | 5.93 |
| 1000+ | 1.14 | 2.34 | 4.11 | 6.02 |

这说明仅靠表中六档公司规模不足以描述套餐间的差异。但规模类别不能捕获全部业务复杂度，也不保证规模、行业、地区、产品与使用量的联合组合有充分可比性。

## 对机制研究意味着什么

本轮缩小的是解释范围：已记录背景与三个使用量代理，在上述模型形式下无法完全替代套餐。它仍不能区分以下解释：

| 尚未区分的机制 | 为什么当前仍不能确认 | 需要的证据 |
|---|---|---|
| 套餐能力或权限影响可用集成 | 数据没有产品与套餐能力、额度或权限字段 | 与具体产品和时期对应的权限，以及客户实际受限任务 |
| 需求较多的客户主动选择高级套餐 | 会话、操作和协作人数只是粗略需求代理；套餐没有历史 | 升级前的具体业务需求、选择理由及套餐变化时间 |
| 合成数据按套餐设置不同集成分布 | 原始字典明确为合成数据，但没有生成过程 | 原始生成代码或可核实的生成说明 |
| 配置帮助促进获得价值并升级 | 本轮没有帮助后配置成功或升级结果 | 已确认的配置障碍、服务分组、配置完成、升级和成本记录 |

这些解释可能并存，不是互斥分类。前面三项涉及观察到的强关联从何而来；最后一项是此前提出的服务干预机制，不能由本轮条件关联推出。

下一步应根据能取得的证据选择具体机制。仅有当前两张表时，可继续做描述性结构检查，但真实需求、权限约束、升级及服务效果仍为CANDIDATE-UNRUN。重复模拟不会增加这些未观测证据。

## 复现与核对

从仓库目录运行：

```bash
python integration_mechanism_v2/experiment.py
```

脚本检查ID、月份、重复、完整性、数值合法性、客户拆分与矩阵秩，保存来源和代码SHA256。输出时间戳会随复跑更新，统计结果应一致。

独立复核已通过：另行从原CSV聚合、构造矩阵并用QR分解复算，不导入主脚本。五模型R²及MSE、24个规模套餐单元人数和均值全部一致。复核者事先看过结果，因此不是盲法；它验证计算，不增加真实客户证据。
