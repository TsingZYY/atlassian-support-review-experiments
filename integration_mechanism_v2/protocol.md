# 套餐与集成：替代解释排查 v2

本轮为已经探索过的比赛合成数据的补充分析。先记录本方案，再运行结果；不声称预注册研究、独立确认或因果识别。不新增观测、不接触用户、不改变此前试点或模拟。

问题：公司规模、行业、地区和产品构成，是否足以在本次模型中替代套餐对集成数量的解释？进一步加入三个使用量代理后，套餐是否仍增加解释力？

单位为客户；结果为2023年1至5月全部产品月记录的平均 Integrations Used，各客户等权。输入仅为客户表、产品使用表及原 integration_plan_v1/protocol.json。客户ID唯一匹配、客户产品月唯一、每产品五个月完整；指标须有限且非负。Active Days不进入模型，不因其已知日历越界而删客户。

固定比较五个含截距OLS模型：P=套餐类别；B=Company Size、Industry、Region类别及产品记录占比；B+P；B+U；B+U+P。U为客户平均 Sessions、Product Actions、Collaborators 各取log1p。类别以训练集定义水平、去掉第一个水平；产品占比去掉一个产品。训练未知类别须报告，不能静默忽略。使用量或产品选择可能是套餐作用后的变量，因此B、U均不能自动视为有效因果调整集，尤其U模型只做条件关联敏感性检查。

报告全队列拟合R²、已有客户拆分上的测试R²和MSE，以及加入套餐的增量R²、残差平方和减少比例；后者不是因果效应。复用原协议按套餐分层、客户ID哈希排序、每组floor(80%)训练的拆分；该测试集此前已使用，本轮不是新留出、未来预测或外部验证。不调参、不搜索显著性、不选择最有利模型。

补充固定Company Size×Plan Type的客户数和客户均值，检查所有层是否覆盖四套餐，以及均值顺序是否一致；不搜索其他细分。客户背景类别粗糙、未观测需求、功能额度、生成规则、选择效应和反向关系仍可能解释剩余关联。强条件关联不能验证配置帮助、升级或利润机制。

解释判据：仅当背景模型能近似替代套餐且加入套餐几乎不改善已有拆分上的误差，才认为当前背景足以解释关联；否则仅说明这些已测变量在该模型形式下不能完全替代套餐。完整报告连续结果，不设事后显著性阈值，不把失败变成零效应。

输出为可复算脚本、JSON、模型比较CSV、规模分层CSV和中文结果说明。源文件及协议、代码SHA256随结果保存，独立复核至少核对主R²、嵌套比较、训练测试客户数、分层人数和均值。
