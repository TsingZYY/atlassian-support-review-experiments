# 配置协助的20人模拟试点：执行前固定方法

用户明确选择执行模拟试点。使用原20人预分配、原票号和产品，不换名单、不重分配；10人配置协助、10人现行支持，每产品各2人。原integration_setup_v1文件保持未执行及结果未知。仅在本目录产生明确标记的假设结果；不联系合成客户、不操作实际账户、不虚构客户原话、具体配置任务或真实付款。

## 事实与假设

比赛数据只提供候选身份/产品、工单主题及历史使用来源；它不提供帮助接受、配置成功或升级概率。原20人资格未确认。本模型明确假设20人都有可被帮助的具体配置需求；该假设不成为原候选的已确认资格。

所有概率、费用和窗口均是预先固定的未校准假设，所有客户使用相同参数。没有用套餐关联、历史使用量或模型生成的性格推断个人购买概率。模型条件结果不得作为实际升级预测或真实试点结果。

## 每人执行流程

1. 协助组收到帮助提议，假设60%接受；控制组维持现行支持。
2. 未接受帮助/控制组的7日配置成功概率为40%。接受帮助者为80%；“帮助无效”情景仍为40%。
3. 30日升级概率由模拟配置结果及情景参数决定。积极情景成功/未成功为35%/5%；无关联均为17%；免费满足需求情景为5%/25%；帮助无效情景仍为35%/5%。这是一套假设的机制方程，不是从原数据估计的中介因果效应。
4. 每次升级贡献200个假设成本单位，针对相同观察窗口，已扣退款及一般新增服务成本，但尚未扣本次帮助费用。每位协助组客户承担提议成本2，接受者另承担15，每个10人帮助批次新增固定成本20。普通支持成本假设两组相同而抵消。

比较全部最初分组客户，包括未接受及配置失败者。每批增量利润=协助组升级净贡献−协助组额外可变费用−对照组升级净贡献−新增固定成本。两组均10人，因此直接总差等价于10倍平均每客差。它不是协助组收入总额，也不代表公司整体利润。

## 四种世界、共同随机数与完整保留

固定四种情景：升级获益、仅配置获益、升级反向、配置无增益。各情景控制组边际升级率均17%，改变的是预设机制。固定seed=2026091311，顺序生成100,000×20的接受、配置、升级三个均匀随机数矩阵；四情景共用这些矩阵以减少场景比较噪声。不同客户在模型中独立。

只保存第0次重复的20人逐条路径，四情景共80行，不能挑选有利一次作为试点。并保存全部100,000批的聚合统计。重复20名假设客户不是新增真实样本，也没有真实等待7天/30天。

解析期望：qA=q0+a(qH−q0)；pA=qA*pS+(1−qA)*pF；pB=q0*pS+(1−q0)*pF。

预期增量利润=10*[(pA−pB)*M−offer_cost−a*assistance_cost]−F。积极/无升级关联/升级反向/配置无效的期望分别为14、−130、−226、−130。该数值在抽样前由参数算出，并非结果挑选。

再枚举单人的接受×配置×升级联合状态并卷积两组净贡献，得到完整批次利润离散分布、严格利润>0的概率与中央95%批次结果范围。联合枚举保留接受帮助、升级和支持成本的依赖；不能将升级与接受成本当作独立。蒙特卡洛均值与概率应在解析/精确值的8个模拟标准误以内，标准误只衡量数值误差。

真实干预次数=0；真实配置成功、升级率与利润均保持null。源名单、证据卡、参数、此协议与主代码锁定SHA256，另由独立脚本复算来源、单批路径、联合分布、成本和模拟统计。
