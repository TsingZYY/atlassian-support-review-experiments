# 客户信息能否增加低满意度识别能力：冻结协议

本轮仅使用比赛的customers.csv、customer_support_tickets.csv、product_usage.csv。此前已看过数据结构、全局摘要及其他实验，因此这是新假设的固定留出探索，不能宣称从未接触过该数据的独立确认试验。此文件和protocol.json须在评分结果运行前冻结，不按结果改样本或阈值。

**假设：在数据合法完整、已关闭且有评分的关联客户中，画像与使用快照能改善留出样本低评分识别。** 标签直接来自原始Customer Satisfaction Rating，1—2分为低评分，3—5分为非低评分。没有新增问答情景或虚构解决标签。

样本要求：唯一规范化邮箱关联；客户若任一关联工单的姓名、年龄或性别与客户表冲突，排除该客户；对应产品2023年1—4月使用记录唯一完整、活跃天数合法、其余使用指标非负有限；Closed工单评分必须合法。每客户只保留最小数字Ticket ID的一张合格票，不按评分值选票。记录逐层排除数量。

按SHA256(split_salt + '|' + Customer ID)排序；最前20个客户作为最终核验样本，其余按同一顺序前20%作为开发集，剩余训练。三组客户不重叠。标签只用于合法性检查和对应分组的训练/评估，不按低分构成重抽测试样本。

比较三组：训练集低分发生率常数；只看产品、类别、主题、优先级、渠道的正则逻辑回归；同算法再加入套餐、行业、地区、公司规模及1—4月使用均值和变化。年龄、性别仅作关联检查，不作预测特征。Resolution、响应/关闭时间、状态及所有评分派生信息不作为输入；5月使用不作为输入。

类别编码、数值标准化只拟合训练集；未知类别按全零编码并报告。两个可学习模型采用同一个预设正则网格，在开发集Brier最小时定版；分数相同选择更强正则。不根据20条测试结果换模型。参数定版文件先写入，再读取测试标签；保存协议、原始CSV、模型和逐例输出哈希。

主指标Brier（预测低分概率与0/1标签的均方误差，越低越好）。探索门槛：相对工单模型下降至少0.02，20客户配对重抽样95%区间的改善下界大于0，且胜过训练集常数模型；测试必须同时有两类。0.02是本轮工程筛选门槛，不是测得的业务收益阈值。每次重抽样只复制原有案例索引，不生成标签或增加独立样本。

另报AUC、log loss、0.5阈值准确率、各模型前5名中的原始低分数；这些不能替代失败的主门槛。测试若只有一类，或区间跨0，保留失败/不确定，不换20条样本。20条不能建立高可靠性或总体效果，所有数值均注明人群。

没有可信的工单创建/评分时间，所以即便使用1—4月记录，也只能称回顾性关联识别，不能证明事前可用或排除倒因果。Closed且有评分及完整关联的筛选结果不能外推Open/Pending客户，更不能转写为真实解决率。

闭环：原始数据与标签 → 冻结假设/对照 → 按客户划分 → 训练与开发定版 → 20条一次核验 → 按预设门槛保留或否定。失败后不继续调参直到成功。
