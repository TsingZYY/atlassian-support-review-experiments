# 解决时间、满意度与成本保本线

**本轮没有发现“响应后间隔越短，满意度越高”的清晰关联。主队列1,357名客户的Spearman相关为0.0030，95%区间[−0.0484, 0.0573]，双侧置换p=0.9108。成本计算器已经可运行，但人工时间节省和实际利润仍未观测。**

本轮按用户最新要求，将研究依据调整为解决时间与满意度。只有比赛合成CSV被当作经验数据。之前提出的真人复核计时未执行，未建设或交付已完成的人评实验，也没有用程序运行时间代替客服工作时间。固定20条继续作来源审核，成本参数另行标明假设。

## 1. 能计算什么时间

字段字典明确：`First Response Time`是首次响应时点，`Time to Resolution`是记录的解决时点。按`DD-MM-YYYY HH:MM`解析原值；源数据包含`31-05-2023`，不能自动按月日推断。没有工单创建时间或客服工作日志。

本轮计算：**响应后间隔＝记录解决时点−首次响应时点**。这是日历间隔，不能叫完整解决耗时、首次响应速度或实际人工处理时长。

| 全8,469张工单的时间状态 | 数量 | 分析处理 |
|---|---:|---|
| 解决时点早于首次响应 | 1,365 | 保留异常记录，不用于时长关联 |
| 正间隔 | 1,402 | 经客户一致性核对后可用于关联 |
| 零间隔 | 2 | 主分析保留，另做排除敏感性 |
| 缺失时间对及评分 | 5,700 | 保留未知，不填零 |

两时戳和评分齐全的2,769票全为Closed，逆序占**49.30%**。不能通过调换时间、取绝对值或补日期“修复”这批记录。按邮箱关联并剔除139名跨表身份冲突客户后，Closed有评分者2,663人，其中1,306票逆序，剩余**1,357人各一票**进入主分析。

这部分仅是原表经质量筛选的子集。约半数时间对逆序、未关闭工单没有评分，会限制代表性；本分析不能说明整个业务的平均处理时间或满意度规律。

## 2. 时间长短与满意度有关系吗

预先固定假设为：较短响应后间隔对应较高评分，即Spearman相关为负。评分是1—5有序值，两变量并列均取平均秩。5,000次打乱评分进行双侧检验；5,000次按客户成对重抽样并重新计算秩给出区间。

| 主检验 | 结果 |
|---|---:|
| 合格客户数 | 1,357 |
| Spearman相关 | **0.0030** |
| 95%重抽样区间 | **[−0.0484, 0.0573]** |
| 双侧置换p | **0.9108** |
| 预设方向是否获支持 | 否 |

为了直观比较，按间隔中位数**6小时23分钟**分组，边界值归入较快组：

| 指标 | 较快组 | 较慢组 |
|---|---:|---:|
| 人数 | 680 | 677 |
| 响应后平均间隔 | 3.01小时 | 12.25小时 |
| 平均满意度 | **3.018 / 5** | **3.052 / 5** |
| 低评分1—2占比 | 38.24% | 37.96% |
| 高评分4—5占比 | 40.00% | 41.51% |

较快减较慢的均分差为**−0.034分**，95%区间[−0.183, 0.115]。数值上较快组略低，但不足以主张“慢一些更满意”。按产品×优先级的20个共同支持层标准化后，差为**−0.020分**，区间[−0.164, 0.126]。剔除两张零间隔票后，相关为0.0011，仍接近零。

这些是预先指定的关联与敏感性检查，没有在看到结果后挑主题、换分组或改变假设。数据已用于前序研究，因此不称全新独立确认。调整仍未消除工单难度、渠道及未测因素；即使有相关，也不能把组间时长差解释为干预能够节省的时间。

## 3. 固定20条到底完成了什么

沿用上一轮全部20张证据卡，不换票。逐一核对原时戳、评分和CSV行号：[20条来源审核](audit_cases_20.csv)。

- 8条时间有序且符合主队列；
- 7条时间逆序，间隔保留空值并注明原因；
- 5条无时间对和评分，保留未知。

例如票5919：首次响应`01-06-2023 02:33`，解决记录`01-06-2023 16:10`，间隔13小时37分，评分2。票4875：首次响应`01-06-2023 23:29`，解决记录`01-06-2023 02:41`，时间逆序；不能擅自把它改成次日解决。

这是20条来源与质量核对，**不是20条人工效率对照**，也不是20个成功解决案例。真正的人评计时、行动效果和盈利结果均待测。

## 4. 成本保本线与可运行计算器

只计算人工成本路径，新增续费/转化收入贡献固定为0。设N为同一评估期的计划处理量，F为新增固定成本，c为每票全部新增变动成本，w为人工小时成本，r为节省时间可兑现为成本下降或额外有价产出的比例。所有成本均为**未校准的假设成本单位**，不是官方价格或现实工资。

`条件净收益 = N × (每票实际劳动分钟节省 ÷ 60 × w × r − c) − F`

`保本所需分钟 = 60 × (c + F/N) ÷ (w × r)`

r为0且成本为正时，无论释放多少时间，都无法通过这条成本路径保本。时间缩短只有转化为可兑现收益才能进入公式。**本轮响应后日历间隔及快慢组的9.23小时均值差均未代入该公式。**

固定基准假设：F=100，c=0.5，w=30。以下比较只是明确的盈亏条件：

| 计划处理量N | 可兑现比例r | 每票保本所需实际劳动时间节省 | 假设每票节省2分钟时的净收益 |
|---:|---:|---:|---:|
| 1,000 | 100% | **1.2分钟** | +400成本单位 |
| 1,000 | 50% | **2.4分钟** | −100成本单位 |
| 1,000 | 0% | 无有限保本线 | −600成本单位 |
| 20 | 100% | **11分钟** | −90成本单位 |

2分钟没有被实测；1,000票只是计划规模，不是样本量或已经覆盖的客户。固定成本按处理量分摊，所以小批量未必保本。完整144种参数组合见[成本网格](cost_break_even_grid.csv)，不只展示赚钱情景。默认不输入节省分钟时，工具只输出保本要求，净收益为null。

```bash
# 只求保本线，不假定实际节省
python resolution_csat_v1/cost_model.py

# 明确是假设：每票节省2分钟，但仅一半能兑现
python resolution_csat_v1/cost_model.py --minutes-saved 2 --realizable-fraction 0.5

# 20票规模的固定成本分摊
python resolution_csat_v1/cost_model.py --volume 20 --minutes-saved 2
```

## 研究决定与复现

当前证据不支持“通过缩短响应后间隔提高满意度，再据此推算利润”的链路。可展示的完整研究是：定义时间指标 → 审核时间质量 → 固定关联对照 → 保留不支持结果 → 给出不依赖虚构收入的成本保本线。时间与满意度可以继续作为并列的体验指标，但暂不能从本轮数据确定优化时间的满意度或利润收益。
